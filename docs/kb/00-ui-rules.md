# UI Rules — Universal Checklist

> 跨專案通用（隨 `00-*` 模板一起複用，換專案直接帶走）。
> 定位：**凡是新增或修改 UI（視窗、對話框、控制項）的工作，動工前必讀 + 交手前自審**。
> 本專案專屬的 UI 架構另見 `docs/kb/coding-rules.md`。
> 範例以 WPF 為準；其他 UI 框架套用同一原則。

---

## 1. UI 自動化測試友善（UI Automation, UIA）

目標：測試程式（FlaUI、WinAppDriver、AI 操作桌面）不靠座標、不靠顯示文字、不靠 `sleep`，就能找到元件、操作元件、讀到結果。

### 1.1 識別

- **每個可互動控制項都設 `AutomationProperties.AutomationId`**：Button、TextBox、ComboBox、CheckBox、RadioButton、
  ListBox／DataGrid、MenuItem、TabItem、Slider。測試要讀值的顯示元件（狀態列文字、結果數字、燈號）也要設。
- **命名**：`{視窗或區塊}_{用途}{控制項類型}`，PascalCase，例 `Settings_SaveButton`、`Main_StatusText`。
  同一視窗內唯一；不含顯示文字、不含索引、不含在地化字串。
- **AutomationId 是對外契約**：改名或刪除等同破壞性變更，要同步改測試，並寫進該輪交付說明。
- **每個 Window 設 AutomationId**（或穩定的 `Title`），供測試定位視窗。Title 會變動（含檔名、計數）時，一定要設 AutomationId。
- **純圖示按鈕**另設 `AutomationProperties.Name`（UIA 與螢幕閱讀器看得到名稱）。
- **動態清單項目**：在 `ItemContainerStyle` 把 AutomationId 綁到穩定鍵（代號、Id、路徑），不用列索引。

### 1.2 可操作

- **優先用標準控制項**。禁止用 `Border`／`TextBlock` + `MouseDown` 充當按鈕：它沒有 Invoke pattern，自動化按不到。
  需要特殊外觀時，改 `Button` 的 `ControlTemplate`。
- **自繪／自訂控制項**（`OnRender`、Canvas 畫圖、第三方圖表）：覆寫 `OnCreateAutomationPeer`，提供對應的 `AutomationPeer`
  與 pattern（Invoke／Value／Selection）。做不到時，旁邊放一個可由 UIA 讀取的文字元件，輸出同一份關鍵資料。
- **每個功能都有鍵盤途徑**（快捷鍵、Tab 順序、Enter／Esc 對應預設鈕與取消鈕）。
- **虛擬化清單**：未捲到的項目不在 UIA 樹。保留標準 `ScrollItemPattern`（不要關掉或覆蓋），大清單另提供搜尋或篩選。

### 1.3 可觀察

- **狀態要能從 UIA 讀到**：忙碌、完成、錯誤各有可讀元件（狀態文字、`IsEnabled`、進度條值）。
  測試用「等到某元件變成某值」判斷完成，不用固定秒數等待。
- **錯誤訊息落在可讀元件**（對話框、狀態列、Toast 文字），不只用顏色或圖示表達。
- **Toast／暫時性提示**：內容同步寫到一個持久的可讀位置（狀態列或記錄），避免消失後測不到。

### 1.4 可測環境

- **提供測試模式**（命令列參數或環境變數）：使用隔離的設定與資料路徑，不污染使用者資料，也不受上次視窗位置影響。
- **啟動完成有明確訊號**：主視窗可互動後，才讓狀態元件顯示「就緒」。

### 1.5 自審

- [ ] 本次新增／修改的互動控制項都有 AutomationId，命名符合規則。
- [ ] 沒有用非互動元件模擬按鈕；自繪控制項有 AutomationPeer 或替代的可讀元件。
- [ ] 非同步操作的開始、完成、失敗，都能從 UIA 讀到。
- [ ] 沒有改動既有 AutomationId；有改動時已列入交付說明。

## 2. 視窗位置與大小持久化

**預設行為：每個可移動或可調整大小的視窗，都記住位置、尺寸、最大化狀態，下次開啟時還原。**
由共用基底處理，視窗不各自手刻。不需要記憶的視窗要明示退出（opt-out）。

### 2.1 做法

- **所有 Window 繼承專案的共用視窗基底**（已有跨專案共用框架時，引用共用框架；沒有時，專案內建一個基底）。
  新增視窗時，只提供一個穩定的 `WindowKey`，其餘由基底處理。
- **退出（opt-out）要明示**：固定大小的訊息對話框、全螢幕 overlay、PoC 視窗，`WindowKey` 回空字串，並用註解寫原因。
- **儲存後端由專案決定**（JSON 檔、SQLite、既有設定服務）。基底只依賴儲存介面，不直接碰檔案或 DB。

### 2.2 行為契約（基底必須做到）

- **還原時機**：`OnSourceInitialized`（視窗顯示前，畫面不閃）。**儲存時機**：關閉時。
- **最大化**：儲存 `RestoreBounds` 與 `IsMaximized`；還原時先套用一般位置，再最大化。**最小化不儲存成最小化**。
- **螢幕變動**：還原前確認視窗落在目前可見的螢幕範圍；不在範圍內時，改用 XAML 預設位置。
- **尺寸下限**：還原的寬高不小於 `MinWidth`／`MinHeight`。
- **WindowKey**：每種視窗一個穩定鍵。同類視窗可開多個時，鍵加上實例識別（例 `Chart:2330`），或共用一個鍵，擇一並寫明。
- **失敗不擋路**：讀寫設定失敗時，視窗照常開關，改用預設值。
- **首次開啟**：沒有紀錄時，用 XAML 的預設尺寸與 `WindowStartupLocation`。
- **測試模式**（見 1.4）：不讀也不寫使用者的視窗設定，或改用隔離的儲存位置。

### 2.3 視窗客製項目

視窗自己的版面狀態，走同一套機制，不另開一套儲存：

- 例：分割線比例、DataGrid 欄寬／欄序／排序、目前分頁、面板收合狀態、縮放比例。
- 基底提供「每視窗一包擴充狀態」（key-value 或一個可序列化的型別）。視窗覆寫「收集狀態」與「套用狀態」兩個鉤子。
- 擴充狀態加版本或容錯：讀到舊格式或缺欄位時，用預設值，不丟例外。

### 2.4 參考實作

- `Solomon_Midas/src/SolomonMidas.UI/Views/WindowBase.cs`（位置／尺寸／最大化記憶、螢幕範圍檢查、失敗降級）。

### 2.5 自審

- [ ] 新視窗繼承共用基底，並提供 `WindowKey`；不記憶的視窗有寫明原因。
- [ ] 沒有在個別視窗手刻位置或尺寸的讀寫。
- [ ] 視窗的版面狀態（欄寬、分割線等）走基底的擴充狀態，沒有另開儲存。
